# Архитектура приложения

Приложение разделено на два независимых слоя: бэкенд и фронтенд. Такое разделение позволяет разрабатывать и тестировать слои изолированно, а также обеспечивает возможность замены GUI без изменения бизнес-логики.

## Общая структура проекта

```
boolean_circuit_editor/
├── src/
│   ├── backend/              # доменная логика, не зависит от GUI
│   │   ├── model/            # модель схемы (Composite)
│   │   │   ├── circuit.py    # класс Circuit — хранилище узлов и связей
│   │   │   ├── node.py       # абстрактный Node и метод accept(visitor)
│   │   │   └── elements.py   # конкретные узлы: AndNode, OrNode, XorNode, …
│   │   ├── commands/         # редактирование и история (Command + Factory)
│   │   │   ├── history.py    # CommandHistory, все классы команд
│   │   │   └── factory.py    # CommandFactory — создание команд
│   │   ├── visitor/          # обход модели (Visitor)
│   │   │   ├── visitor.py    # абстрактный CircuitVisitor
│   │   │   └── node_roles.py # NodeRolesVisitor — определение типов пинов
│   │   ├── io/               # загрузка/сохранение (Builder)
│   │   │   └── xml_builder.py # export_to_xml / import_from_xml
│   │   ├── logic/            # вычислительные алгоритмы
│   │   │   └── truth_table.py # таблица истинности, упрощение, полиномы
│   │   └── application/      # фасад для фронтенда
│   │       └── app_controller.py
│   └── frontend/             # GUI на PyQt6
│       ├── app/              # главное окно, запуск
│       ├── canvas/           # рабочая область (QGraphicsScene/View)
│       ├── panels/           # боковые панели (таблица, упрощение, полиномы)
│       ├── dialogs/          # диалоговые окна (настройки, ошибки)
│       └── common/           # SettingsManager — настройки отображения
├── tests/
│   ├── unit/                 # модульные тесты (pytest)
│   ├── integration/          # интеграционные тесты (pytest)
│   └── fixtures/             # тестовые XML-файлы
├── docs/                     # документация, UML-диаграммы
├── requirements.txt
└── run.py                    # точка входа
```

## Используемые паттерны

### Composite — модель схемы

Модель булевой схемы строится по паттерну Composite. Абстрактный класс `Node` (`backend/model/node.py`) представляет любой элемент схемы и объявляет метод `accept(visitor)`. Конкретные классы-узлы (`AndNode`, `OrNode`, `XorNode`, `EqualNode`, `InputNode`, `OutputNode`, `Const0Node`, `Const1Node`) наследуют `Node` и определяют своё поведение. Контейнер `Circuit` (`backend/model/circuit.py`) хранит плоский список узлов и список связей в виде кортежей `(out_node_id, out_pin, in_node_id, in_pin)`.

Такой подход позволяет единообразно обрабатывать любой узел через посетителей и легко расширять набор элементов, не меняя существующего кода.

### Command — операции редактирования

Каждое действие пользователя оборачивается в объект команды с методами `execute()` и `undo()`. В `backend/commands/history.py` реализованы пять классов команд:

| Команда | Описание |
|---------|----------|
| `AddNodeCommand` | Добавление узла в схему |
| `RemoveNodeCommand` | Удаление узла и всех его связей |
| `MoveNodeCommand` | Перемещение узла (хранит старые и новые координаты) |
| `ConnectPinsCommand` | Создание связи между пинами |
| `DisconnectPinsCommand` | Удаление связи |

Класс `CommandHistory` хранит стек выполненных команд и стек отменённых команд, обеспечивая полную поддержку Undo/Redo. Выполнение новой команды после Undo очищает стек Redo.

### Visitor — обход модели

Для операций, требующих обхода узлов схемы, используется паттерн Visitor. Абстрактный класс `CircuitVisitor` (`backend/visitor/visitor.py`) объявляет методы `visit_*` для каждого типа узла. Конкретная реализация `NodeRolesVisitor` (`backend/visitor/node_roles.py`) при обходе собирает идентификаторы входных и выходных узлов схемы. Visitor используется командами для сохранения и восстановления состояния при Undo/Redo.

### Factory — создание команд

`CommandFactory` (`backend/commands/factory.py`) централизованно создаёт объекты команд по заданным параметрам. Это упрощает код контроллера, делает создание команд единообразным и позволяет добавлять валидацию или логирование в одном месте.

```python
factory = CommandFactory(circuit)
cmd = factory.create_connect_pins(src_id, out_pin, dst_id, in_pin)
history.execute(cmd)
```

### Builder — загрузка и сохранение XML

Функции `export_to_xml` и `import_from_xml` в `backend/io/xml_builder.py` реализуют паттерн Builder для работы с XML-форматом схемы. При загрузке Builder поэтапно строит объект `Circuit`: сначала создаёт все узлы, затем добавляет связи. При сохранении схема преобразуется в XML-дерево с помощью `xml.etree.ElementTree`. Такой подход изолирует формат хранения от остальной логики.

## Взаимодействие слоёв

```
Пользователь → Frontend (PyQt6)
                   ↓ вызов методов
              AppController (фасад)
                   ↓                    ↓
         CommandFactory           Logic (truth_table.py)
                   ↓
         CommandHistory.execute(cmd)
                   ↓
              Circuit (модель)
```

1. Пользователь взаимодействует с GUI (фронтенд).
2. Фронтенд вызывает методы `AppController` — единственную точку входа в бэкенд.
3. Контроллер создаёт команду через `CommandFactory` и передаёт её в `CommandHistory`.
4. Команда выполняет изменения в `Circuit` и сохраняет данные для Undo (при необходимости — через Visitor).
5. После выполнения команды GUI обновляется (перерисовывается сцена).
6. При Undo/Redo `CommandHistory` вызывает `undo()` или `execute()` соответствующей команды.
7. Вычислительные функции (таблица истинности, упрощение, полиномы) не изменяют модель (за исключением команды упрощения) и вызываются контроллером напрямую.

## Архитектурные преимущества

Применение паттернов обеспечивает:

- **Гибкость** — новые типы элементов добавляются без изменения существующего кода.
- **Расширяемость** — новые алгоритмы реализуются через новых посетителей.
- **Тестируемость** — бэкенд полностью отделён от GUI и тестируется без запуска интерфейса.
- **Поддержку** — чёткое разделение ответственности упрощает локализацию ошибок.
