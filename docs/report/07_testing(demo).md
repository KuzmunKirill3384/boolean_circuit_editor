# Тестирование

Тестирование проекта редактора булевых схем проводилось на трёх уровнях: **модульном**, **интеграционном** и **ручном**. Цель — обеспечить корректность работы всех компонентов, соответствие функциональным требованиям и стабильность ключевых сценариев.

## 1. Модульные тесты (Unit Tests)

Модульные тесты расположены в каталоге `tests/unit/` (и рядом с основными модулями). Используется фреймворк `pytest`.

### Покрытие модулей

| Модуль | Основные тестируемые функции | Файл тестов |
|--------|------------------------------|-------------|
| Модель схемы (`Circuit`) | Добавление/удаление узлов, соединение пинов, валидация, обнаружение циклов | `test_circuit.py` |
| Команды и история | `AddNodeCommand`, `RemoveNodeCommand`, `MoveNodeCommand`, `ConnectPinsCommand`, `DisconnectPinsCommand`, `CommandHistory` | `test_history.py`, `test_command_factory.py` |
| Логика схемы | Таблица истинности, вычисление, упрощение, полиномы, влияющие узлы | `test_logic.py` |
| Visitor / Composite | Паттерн Посетитель, роли узлов, композитная структура | `test_visitor.py`, `test_composite.py` |
| XML (IO) | Экспорт/импорт, roundtrip, обработка ошибок | `test_xml.py` |
| Интеграционные workflow | Полные сценарии: создание → вычисление → сохранение/загрузка → undo/redo | `test_workflows.py` |

### Примеры ключевых тестов

**Модель Circuit:**
- Добавление узлов с проверкой типа и координат
- Запрет множественного подключения к одному входному пину
- Обнаружение циклов при соединении
- Автоматическое удаление связей при удалении узла

**Логика (truth_table):**
- Корректность таблиц истинности для AND, OR, XOR, EQUAL
- Упрощение схемы (`simplify`) с заменой IN на CONST_0/CONST_1
- Полиномиальное представление (`get_polynomials`)
- Согласованность `evaluate_circuit` и `get_truth_table`

**Команды и история:**
- Полный цикл execute → undo → redo для всех типов команд
- Очистка redo-стека после новой команды
- Сохранение связей при undo/redo операций удаления

## 2. Интеграционные тесты

Интеграционные тесты (`test_workflows.py`) проверяют совместную работу нескольких модулей:

- **Полный workflow**: создание схемы → вычисление → экспорт в XML → импорт → проверка таблицы истинности
- **Undo/Redo цепочки**: множественные connect-команды, undo/redo в любом порядке
- **XML roundtrip**: сохранение/загрузка сохраняет структуру, id узлов, связи и логику
- **Упрощение + XML**: упрощённая схема остаётся валидной и корректно вычисляется
- **Обработка ошибок**: загрузка повреждённого XML вызывает исключение
- **Сложные схемы**: AND → XOR → OR, длинные цепочки из 10 AND-вентилей

Все интеграционные сценарии успешно проходят.

## 3. Ручное тестирование (GUI)

Ручное тестирование выполнялось по расширенному чек-листу, учитывающему реальную реализацию приложения.

### Основные проверенные сценарии

- Добавление всех типов элементов (IN, OUT, AND, OR, XOR, EQUAL, CONST)
- Создание и удаление связей с валидацией (запрет циклов, превышения входов)
- Undo/Redo после любых операций (перемещение, удаление, соединение)
- Таблица истинности (вся схема и по выбранному узлу с подсветкой)
- Упрощение схемы с предварительной оценкой удаляемых элементов
- Полиномиальное представление для любого узла
- Сохранение/загрузка XML (включая roundtrip и обработку некорректных файлов)
- Валидация структуры схемы в реальном времени

**Тестовые данные:**
- `simple_and.xml`, `xor_circuit.xml`
- Повреждённые XML для проверки обработки ошибок: `half_adder.xml`

## 4. Запуск тестов

```bash
# Все тесты
pytest tests/

# Только модульные
pytest tests/unit/

# С покрытием
pytest --cov=backend tests/
```

**Результаты на момент финальной версии:**
- Все модульные и интеграционные тесты **проходят** (100% успешных запусков)
- Покрытие бизнес-логики и модели — **более 85%**
- Критические сценарии (undo/redo, XML roundtrip, упрощение) покрыты полностью

## 5. Выводы

Система демонстрирует высокую стабильность. Интеграция модулей (модель + команды + история + логика + IO) работает корректно. Все основные пользовательские сценарии, описанные в руководстве оператора, подтверждены как на уровне автоматизированных тестов, так и вручную.
