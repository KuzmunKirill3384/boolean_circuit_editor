# Алгоритмы

В данном разделе описываются ключевые алгоритмы, реализованные в приложении: генерация таблицы истинности, поиск влияющих элементов, упрощение схемы, полиномиальное представление и валидация структуры.

## 1. Генерация таблицы истинности

Для вычисления таблицы истинности применяется метод полного перебора комбинаций входных сигналов с последующей симуляцией схемы.

### Алгоритм
1. Определяются все входные узлы схемы (тип `IN`). Пусть их количество равно `n`.
2. Перебираются все `2^n` комбинаций значений на входах (от 0 до `2^n - 1`). Для каждой комбинации:
   - Значения на входах устанавливаются в соответствии с битами комбинации.
   - Выполняется симуляция схемы в топологическом порядке (рекурсивный обход с мемоизацией): значения вычисляются от входов к выходам, следуя связям. Для каждого логического элемента значение определяется по его типу (`AND`, `OR`, `XOR`, `EQUAL`) и значениям на его входах.
   - Сохраняются значения на всех выходных узлах (`OUT`).
3. Результат формируется в виде списка строк с заголовками: входы (`IN_<id>`) и выходы (`OUT_<id>`).

### Обоснование
Полный перебор всех комбинаций гарантирует точность и простоту реализации. Для схем с числом входов до 10–12 (что типично для учебных задач) этот метод работает быстро (1024–4096 комбинаций). При большем количестве входов пользователь вряд ли сможет визуально анализировать таблицу, поэтому дальнейшая оптимизация не требуется.

## 2. Поиск влияющих элементов

Для определения узлов, от которых зависит значение выбранного элемента, используется обход графа в обратном направлении.

### Алгоритм
1. Создаётся множество `visited`, инициализируемое выбранным узлом.
2. Для текущего узла находятся все узлы-источники, соединённые с его входами (т.е. узлы, выходы которых подаются на вход данного узла).
3. Каждый найденный источник добавляется в `visited`, и процесс рекурсивно повторяется для него.
4. Итоговое множество содержит все узлы, влияющие на значение исходного элемента.

### Обоснование
Алгоритм имеет линейную сложность O(N + E), где N – число узлов, E – число связей, что оптимально для графа схемы. Результат позволяет визуально выделить влияющие элементы при анализе конкретного узла.

## 3. Упрощение схемы при фиксированных входах

Если пользователь фиксирует значения некоторых входов, схема может быть упрощена путём замены фиксированных входов на константные источники и удаления узлов, не влияющих на выходы.

### Алгоритм
1. Создаётся копия текущей схемы для безопасного упрощения.
2. Для каждого входа, значение которого задано пользователем (0 или 1), соответствующий узел заменяется на константный источник (`CONST_1` при 1, `CONST_0` при 0).
3. Выполняется поиск всех узлов, достижимых от выходов схемы (обход в обратном направлении от `OUT`). Узлы, не попавшие в это множество, не влияют на выходы и могут быть удалены.
4. После удаления недостижимых узлов схема сохраняет эквивалентное поведение при заданных фиксированных входах.

### Оценка количества удаляемых элементов
Для каждого входа `IN_i` выполняется моделирование упрощения при фиксации его в 0 и в 1. Для обоих случаев подсчитывается, сколько узлов удаляется по сравнению с исходной схемой. Результат представляется в виде пары чисел `if_0` и `if_1`, показывающих потенциальную выгоду от фиксации этого входа. Эти оценки выводятся пользователю до выполнения реального упрощения.

### Обоснование
Алгоритм использует методы константной пропагации и удаления "мёртвого кода". Он работает быстро и даёт наглядную оценку, позволяя пользователю понять, какие входы целесообразно фиксировать для уменьшения размера схемы.

## 4. Полиномиальное представление

Для каждого логического элемента строится строковое выражение, отражающее его функцию в базисе операторов `AND` (`*`), `OR` (`+`), `XOR` (`⊕`) и `EQUAL` (`=`).

### Алгоритм
1. Инициализируется словарь мемоизации `memo`, чтобы избежать повторных вычислений для уже обработанных узлов.
2. Для заданного узла `node_id` рекурсивно определяется его строковое представление:
   - Если узел уже вычислен, возвращается сохранённая строка.
   - Если узел – вход (`IN`), возвращается `x<id>`.
   - Если узел – константа (`CONST_0` или `CONST_1`), возвращается `"0"` или `"1"`.
   - Если узел – выход (`OUT`), в качестве выражения берётся выражение его единственного источника.
   - Если узел – логический элемент (`AND`, `OR`, `XOR`, `EQUAL`), рекурсивно получаются выражения для всех его входов, которые соединяются символом соответствующей операции. Выражение заключается в скобки, например `(expr1 * expr2)` для `AND`.
3. Результат сохраняется в `memo` и возвращается.

### Пример
Для схемы из двух входов (0 и 1), соединённых с элементом `XOR`, полиномиальное представление будет иметь вид `(x0 ⊕ x1)`.

### Обоснование
Такой подход даёт наглядное представление функции элемента в терминах исходных логических операций схемы. Он прост в реализации и не требует преобразования к канонической форме (полином Жегалкина). Выражение легко читается и полностью соответствует структуре схемы. При необходимости в дальнейшем можно добавить получение канонического полинома через таблицу истинности.

## 5. Валидация схемы

При создании или изменении соединений проверяются следующие условия:

- **Существование узлов**: идентификаторы источника и приёмника должны присутствовать в текущей схеме.
- **Допустимость пинов**: номера выходного пина источника и входного пина приёмника должны быть в допустимых пределах (определяются типом узла).
- **Отсутствие конфликта подключений**: один входной пин не может иметь более одного источника сигнала.
- **Отсутствие циклов**: добавление новой связи не должно создавать ориентированный цикл в графе схемы.

### Алгоритм проверки циклов
При попытке добавления связи `(out_node → in_node)` выполняется поиск в глубину (DFS) от `in_node` по существующим связям. Если в ходе обхода достигается `out_node`, фиксируется попытка создать цикл, и соединение запрещается. Дополнительно полная структурная валидация `validate_structure()` повторно проверяет отсутствие циклов во всей схеме.

### Обоснование
Комбинационные схемы обязаны быть ацикличными, иначе нарушается детерминированность вычислений и появляется неопределённое состояние. Проверка на этапе каждого соединения предотвращает построение некорректных схем и сопровождается понятным сообщением об ошибке.
