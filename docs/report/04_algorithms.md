# Алгоритмы

В данном разделе описываются ключевые алгоритмы, реализованные в `backend/logic/truth_table.py`, а также алгоритмы валидации из `backend/model/circuit.py`.

## 1. Генерация таблицы истинности

### Алгоритм (`get_truth_table`, `get_truth_table_for_node`)

1. Определяются все входные узлы схемы (тип `IN`) и все выходные (тип `OUT`). Пусть входов `n`.
2. Перебираются все `2^n` комбинаций значений (от `0` до `2^n − 1`). Для каждой комбинации:
   - Значения входов устанавливаются по битам числа-комбинации.
   - Выполняется симуляция схемы: значение каждого узла вычисляется рекурсивно с мемоизацией (словарь `memo`), обход идёт от выходов к входам. Для логических элементов применяется соответствующая операция: `AND` — `a & b`, `OR` — `a | b`, `XOR` — `a ^ b`, `EQUAL` — `int(a == b)`.
   - Сохраняются значения на всех выходных узлах (`OUT`).
3. Результат — список строк-словарей с ключами `IN_<id>` и `OUT_<id>`.

Для `get_truth_table_for_node` алгоритм аналогичен, но в каждой строке сохраняется значение только заданного узла (ключ `Node_<id>`).

### Обоснование

Полный перебор всех комбинаций гарантирует точность. Для учебных схем с числом входов до 10–12 (1024–4096 строк) метод работает мгновенно. Мемоизация внутри одной комбинации устраняет повторные вычисления одного узла.

## 2. Поиск влияющих узлов

### Алгоритм (`get_affected_nodes`)

1. Строится обратный граф схемы: для каждого узла определяется список узлов-источников его входных пинов.
2. Из заданного узла запускается обход в глубину (DFS) по обратным рёбрам.
3. Посещённые узлы (кроме самого исходного) образуют множество «влияющих» — тех, от которых зависит значение данного узла.

### Обоснование

Алгоритм имеет сложность `O(N + E)`, где `N` — число узлов, `E` — число связей. Результат используется для подсветки на сцене при просмотре таблицы истинности по элементу.

---

## 3. Упрощение схемы при фиксированных входах

### Алгоритм (`simplify`)

1. Создаётся глубокая копия схемы (`Circuit`) для безопасного изменения без мутации оригинала.
2. Для каждого зафиксированного входа `IN` соответствующий узел заменяется на `CONST_0` (при значении 0) или `CONST_1` (при значении 1). Связи узла не меняются — константный источник продолжает питать те же пины.
3. Выполняется поиск узлов, достижимых от выходов схемы: обход в обратном направлении от всех `OUT`-узлов по входным связям (аналогично п. 2).
4. Узлы, не вошедшие в множество достижимых, не влияют ни на один выход и удаляются из копии схемы вместе со своими связями.

**Важно:** замена `IN → CONST` происходит немедленно; удаление недостижимых узлов происходит только если их можно достичь из выходов без фиксированного входа. На практике в простых схемах (IN → AND → OUT) константный узел остаётся достижимым, поэтому размер схемы не уменьшается — только тип узла меняется.

### Оценка количества удаляемых элементов (`get_removable_count_per_input`)

Для каждого входного узла `IN_i` выполняется два пробных вызова `simplify` (при значении 0 и при значении 1). Для каждого случая подсчитывается разница в числе узлов между пробной упрощённой копией и оригиналом. Результат — словарь вида `{node_id: {"if_0": count, "if_1": count}}`.

### Обоснование

Алгоритм основан на константной пропагации и удалении «мёртвого кода» — стандартных методах оптимизации компиляторов. Работа с копией гарантирует сохранность оригинальной схемы. Предварительная оценка позволяет пользователю принять информированное решение.

## 4. Полиномиальное представление

### Алгоритм (`get_polynomial_for_node`, `get_polynomials`)

1. Инициализируется словарь мемоизации `memo`.
2. Для заданного узла рекурсивно строится строковое выражение:
   - `IN` → `x<id>`
   - `CONST_0` → `"0"`, `CONST_1` → `"1"`
   - `OUT` → выражение его единственного источника
   - Логический элемент (`AND`, `OR`, `XOR`, `EQUAL`) → рекурсивно получаются выражения для всех входов; они объединяются символом операции и заключаются в скобки. Например, `(x0 * x1)` для AND.
3. Результат сохраняется в `memo` во избежание повторных вычислений.

`get_polynomials` вызывает `get_polynomial_for_node` для каждого узла схемы и возвращает словарь `{node_id: str}`.

### Пример

Схема: `IN(id=0)`, `IN(id=1)` → `XOR` → `OUT`. Полином XOR-узла: `(x0 ⊕ x1)`.

### Обоснование

Рекурсивное построение выражения по структуре схемы просто в реализации и наглядно для пользователя. Выражение точно отражает функцию узла в терминах исходных входов..

## 5. Валидация схемы

При попытке добавления связи `circuit.connect_pins(out_node, out_pin, in_node, in_pin)` последовательно проверяются условия:

1. **Существование узлов**: оба идентификатора должны быть в схеме.
2. **Допустимость пинов**: индексы пинов должны быть в пределах допустимого диапазона, определяемого типом узла.
3. **Занятость пина**: входной пин не должен уже иметь источника.
4. **Отсутствие цикла**: добавление связи не должно создавать ориентированный цикл.

### Алгоритм проверки циклов

При попытке добавить связь `A → B` запускается DFS из узла `B` по существующим прямым рёбрам графа. Если в ходе обхода достигается узел `A` — связь создала бы цикл, и она отклоняется. Дополнительно метод `validate_structure()` проверяет отсутствие циклов во всей схеме (топологическая сортировка).

### Обоснование

Комбинационные схемы обязаны быть ацикличными — иначе вычисление значений становится неопределённым. Проверка на каждой попытке соединения предотвращает некорректные схемы и сопровождается понятным сообщением об ошибке пользователю.
